## 数据冻结前

- 核对 XML 坐标约定，抽查转换后预览。
- 检查 audit.json 中被隔离的样本、各类数量和来源比例。
- 补充道路/序列分组或近重复分组；准备数据时仅自动合并字节相同图片，另用 duplicates 命令筛查近重复候选。
- 每个集合至少覆盖四类；缺少类别时调整数据和分组，不以零样本类别 AP 得结论。
- 保存 splits/*.jsonl、audit.json、数据来源和许可说明。生成目录默认被 Git 忽略，发布前将小型清单复制到 reports/ 并检查路径信息。

## 部署验收

- 同一个最佳权重导出 ONNX，固定 imgsz、FP32、batch=1。
- 同一验证集分别评估 PT 和 ONNX。
- 框架 val 的 speed 只作诊断；另做预热、同步设备、重复计时，记录中位数/P95。
- 完整延迟应包含图像预处理、推理与后处理；是否含文件 I/O 单独注明。
- 独立 ONNX Runtime 推理和 CPU 延迟 benchmark 已完成；结果与范围见 [部署验收](../reports/deployment-validation.md)。GPU 和完整服务延迟仍待单独验收。
